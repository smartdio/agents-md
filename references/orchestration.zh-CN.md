# 协作参考：模板与能力边界

简体中文译版 · [English（主版本）](orchestration.md)。内容以英文主版本为准。

仅在复杂委派、交接或能力疑问时读取。核心执行规则以根目录 AGENTS.md 为准；以下模板按需取用，不要求每轮填表。

## 复杂任务包

```text
角色与工作线：
本轮目标／不做什么：
必要背景与已确认决策：
输入、精确路径与产物版本：
允许修改的文件／资源：
接口、依赖与不可破坏的约束：
验收标准及适用的运行方法：
可复用的证据：
预期交付与返回格式：
```

简单任务只需明确目标、输入、修改边界与验收要求。原代理续派只补充增量；不要重复发送已稳定的背景，也不要遗漏新的约束。

## 结果与替换交接

```text
状态：完成／部分完成／阻塞
结论：简洁结论及必要理由
产物：修改路径与版本标识
验证：执行内容、结果与证据路径
风险：未验证项、限制或可能影响
下一步：需要协调者处理的具体事项
```

替换代理时另补充必要决策、未解决问题和已排除的失败方案，供新代理继续；不要求复制完整历史。详细日志仅在有后续价值时保留，不输出内部推理记录。

失联不代表执行已经停止，发出中断也不等于外部工具或后台操作已停止。接管同一资源前须核对遗留变更，并确认原执行者及仍在运行的相关操作已停止写入；无法确认时，不安排新执行者并发接管该资源，可继续不受影响的独立工作。

## 能力边界

- AGENTS.md 是行为规范，不是可执行调度程序，不能保证工具能力或配置生效。
- 子 Agent 的模型选择与推理深度是两个独立决定。模型可用性和逐代理覆盖能力取决于当前接口；当工具支持显式覆盖时，默认子代理模型不要求所有子 Agent 都使用它。
- 首次不继承主历史，不等于每轮清空专业代理的上下文。续派须使用实际原代理标识；新建同名代理不是恢复。
- 不保证跨新任务、重启或恢复后原代理仍可访问；项目文件承载关键状态，但不等于保存完整代理会话。
- 实际模型与推理覆盖参数以当前接口为准。原代理不能动态调整时，先考虑补充精确信息，或只把有界疑难问题交给更强模型或更高推理深度的代理，不必丢弃整条工作线。

能力依据：[OpenAI 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。这些说明沿用初始规范的边界；工具变化时需重新核对，不应视为永久能力承诺。

## 成本评估

并行可能缩短耗时，但不保证降低总消耗。若已有可用测量，合计主代理与全部子代理的消耗，并结合质量及返工比较；区分 token、缓存计费和订阅额度。未测量则明确无法量化，不为证明节省专门增加昂贵流程。
